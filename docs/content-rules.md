# 文章のルール

サイトの文章は、参照HTMLと `content/` にあるものをそのまま使います。このルールは、デザインにない文言（エラー、404、新しい記事など）を書くときと、表記に迷ったときに使います。

## 1. 日本語

- **文体：**
  - です・ます調で書く
  - 1文は60字程度までにする
  - 感嘆符は使わない
- **ひらがなで書く語：** こと、とき、もの、ため、よう、など、ほか、ください、できる、ある、ない、いただく
- **数字と記号：**
  - 英数字は半角にする
  - 数字と単位の間は空けない（3営業日、2026年10月1日、4か月）
  - 括弧は全角の「」（）を使う
- **日付：**
  - 本文では「2026年10月1日」と書く
  - 記事の日付欄など、一覧の表示では「2026.10.01」と書く
- **番号：** 見出しや手順の番号は漢数字（一、二、三）にする。本文の数量は算用数字にする
- **製品名：**
  - 「Pixie CAASM」「Pixie EASM」「Pixie IASM」「Pixie ASPM」「Pixie for Operations」と書く
  - 4つまとめて言うときは「Pixieの4製品」
- **社名：** 「株式会社衝動」と書く。文中で繰り返すときは「当社」でよい（ポリシー類）
- **開発中の製品：**
  - Pixie for Operationsの機能は構想の段階なので、実現済みのように書かない
  - 「示します」と書いてよいのは、その製品の設計を説明する場面だけにする
  - 成果を約束する表現（「必ず」「数分で」など）は使わない
- **根拠のない数字を書かない：** 導入社数、検出率、時間短縮などの数字を書かない
- **被害企業の名前：** 実在の被害企業の名前を本文に書かない
- **法令の扱い：** 法令と制度に触れるときは、記事の出典欄に資料名と日付を書く。制度解説案などの確定していない情報は、そうだと明記する

## 2. 英語

- **綴りと文体：**
  - 米国式の綴りを使う
  - 見出しは文頭だけを大文字にする（Sentence case）
  - 並列の最後の項目の前にもカンマを付ける（serial comma）
  - 引用符は曲がった形（“ ” ’）を使う
  - 感嘆符は使わない
- **社名：**
  - 「Shodo Inc.」と書く
  - 社名の由来を説明するときだけ「Shodō (衝動)」と書く
- **日付：** 「Oct 1, 2026」
- **日本の制度：**
  - 英語版では、日本の制度の細部に触れない
  - 必要なら「regulatory notification」「Japan’s new cyber response law」のように一般的な言葉で書く
- **Pixie for Operationsの注記：** 英語版では、「日本の組織向けに先に設計している」と必ず書く
